## `> cat projects/`

<details>
<summary><b>⚙️ Container Runtime with Kernel Memory Monitoring</b> &nbsp;·&nbsp; <code>C</code> <code>Linux namespaces</code> <code>Kernel module</code></summary>
<br/>

> A container runtime written from scratch. `clone()` with **PID, UTS and mount namespaces**, a supervisor CLI, and a loadable kernel module that reads `get_mm_rss()`, warns at a soft limit and `SIGKILL`s the process past its hard limit — no cgroups, no libcontainer. The README documents the five ways it is *not* production-grade.

[![Repo](https://img.shields.io/badge/View_Repo-181717?style=flat-square&logo=github)](https://github.com/DARKDRAGON02/container-runtime-monitor)

</details>

<details>
<summary><b>🔒 Secure-Vault-AI</b> &nbsp;·&nbsp; <code>TypeScript</code> <code>Next.js</code> <code>Node.js</code> <code>Web Crypto</code></summary>
<br/>

> AES-256-GCM on both legs — the browser encrypts through `crypto.subtle` with a fresh 12-byte IV, the Node relay decrypts to call Gemini and re-encrypts the reply. **It is not end-to-end encrypted**, because the client sends the key. The README says that plainly and documents the ECDH construction that would fix it.

[![Repo](https://img.shields.io/badge/View_Repo-181717?style=flat-square&logo=github)](https://github.com/DARKDRAGON02/Secure-Vault-AI)
